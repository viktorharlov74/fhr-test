## Задание 1 - Пузырьковая сортировка

**Страница:** `GET /sorting`
Для запуска надо нажать сортировать.

**Что реализовано:**

- Генерация файла с данными через кнопку на странице или команду:
  ```bash
  ./vendor/bin/sail artisan sorting:generate 200000
  ```
  Файл сохраняется в `storage/data/data.txt`.

- Страница показывает первые 20 элементов из файла до запуска сортировки. 
- После выбора количества элементов - отображает
  срез до и после сортировки, время выполнения и потреблённую память.

**Реализация сортировки:** `app/Services/Sorting/BubbleSortService.php`

Две оптимизации:

1. Флаг $swapped - если за проход не было ни одного обмена, массив уже отсортирован, выходим досрочно. В лучшем случае
   даёт O(n) вместо O(n²).
2. Сужение верхней границы - после каждого прохода последний элемент гарантированно на месте, уменьшаем
   границу цикла. Сокращает число итераций примерно вдвое.

**Архитектура:**

| Файл                                         | Ответственность                          |
|----------------------------------------------|------------------------------------------|
| `app/Contracts/SortInterface.php`            | Интерфейс алгоритма сортировки           |
| `app/Services/Sorting/BubbleSortService.php` | Реализация пузырьковой сортировки        |

**Тесты:** `tests/Unit/Sorting/BubbleSortServiceTest.php`

```bash
./vendor/bin/sail test tests/Unit/Sorting/BubbleSortServiceTest.php
```

## Задание 2 - Схема БД: игроки по сезонам

**Дамп:** `database/dump.sql`

**Миграции:** `database/migrations/`

**Схема таблиц:**

- `cities` - города (название на русском и английском)
- `leagues` - лиги
- `clubs` - клубы (название на рус/англ, привязка к городу и лиге)
- `seasons` - сезоны (год начала и окончания)
- `players` - игроки (ФИО на рус/англ, вес, рост)
- `player_season` - сводная таблица (игрок + сезон + клуб + номер + статус)

Связь "игрок–клуб" вынесена в `player_season`.

**Наполнение:** 3 города, 1 лига (КХЛ), 3 клуба, 2 сезона, 9 игроков, часть игроков меняет клуб между сезонами.

```bash
# Применить миграции и сидер для наполнения
./vendor/bin/sail artisan migrate
./vendor/bin/sail artisan db:seed --class=PlayerSeasonSeeder
```

## Задание 3 - Выгрузка пользователей в CSV

**Страница:** `GET /export`

Чтобы пользователи появились их нужно сгенерировать.
Генерация пользователей выполняется ./vendor/bin/sail artisan persons:generate

**Что реализовано:**

- Генерация пользователей ./vendor/bin/sail artisan persons:generate
- По нажатию кнопки запускается пошаговая выгрузка через AJAX 
- Прогресс-бар отображает прогресс в реальном времени.
- После завершения автоматически начинается скачивание файла.
- Поля для выгрузки выбираются чекбоксами (Фамилия, Имя, Телефон, E-mail).

**Архитектура:**

| Файл                                          | Ответственность                          |
|-----------------------------------------------|------------------------------------------|
| `app/Contracts/PersonRepositoryInterface.php` | Интерфейс доступа к таблице persons      |
| `app/Repositories/PersonRepository.php`       | Реализация через `DB::table()`           |
| `app/Contracts/ExportServiceInterface.php`    | Интерфейс сервиса экспорта               |
| `app/Services/Export/ExportService.php`       | Логика инициализации и обработки чанков  |
| `app/Http/Controllers/ExportController.php`   | Только DI + делегирование + возврат JSON |

**API:**

| Метод  | URL                     | Описание                                                 |
|--------|-------------------------|----------------------------------------------------------|
| `GET`  | `/export`               | Страница с формой                                        |
| `POST` | `/export/start`         | Инициализация: создаёт файл, возвращает `ExportStartDTO` |
| `POST` | `/export/chunk`         | Обработка чанка, возвращает `ExportChunkDTO`             |
| `GET`  | `/export/download/{id}` | Скачивание готового файла                                |
